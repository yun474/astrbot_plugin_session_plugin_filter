# 会话插件过滤

按会话给 AstrBot 插件开**白名单 / 黑名单**，还能把插件设成某些群**专属**，带可视化配置面板。

原生「自定义规则」只能一个会话一个会话地禁用插件，想让某个群只能用几个插件，得把其他插件挨个点掉，装了新插件还得回去补。也没法让某个插件只在指定的群里用。这个插件就是来解决这两个问题的。

## 一条规则能做什么

一条规则 = **一组会话** + **一组插件**：

- **只允许勾选的插件**（白名单）：这些会话里只有勾选的插件能用，其余插件全部失效，新装的插件默认也被挡在外面
- **禁用勾选的插件**（黑名单）：这些会话里勾选的插件被禁用，其余照常
- **专属**：插件旁边点「专属」，这个插件就只能在这些会话里用，其他所有会话都用不了

举个例子，想让「游戏群」只能用 3 个插件，其中「抽卡」插件只给游戏群用：

1. 新建规则，会话里添加游戏群
2. 选「只允许勾选的插件」，勾上这 3 个插件
3. 在「抽卡」那一行点「专属」

编辑器顶部会用一句话描述这条规则的效果，配完看一眼就知道对不对。

## 多条规则怎么算

- 一个会话命中多条规则时**叠加生效**：插件要被每一条都放行才能用
- 同一个插件被多条规则设为专属时，在这些规则的会话里都能用
- 没有规则影响的会话，所有插件照常工作
- 系统内置插件永远不受影响

## 会话写法

- 在面板里按群名或会话 ID 搜索添加；会话 ID 也可以在聊天里发 `/sid` 拿到
- 通配符：`*` 匹配任意字符，`?` 匹配单个字符，例如 `*:GroupMessage:*` 是所有群聊
- 排除：在前面加 `!`，例如先加「所有群聊」，再加 `!aiocqhttp:GroupMessage:123456`，就是除了这个群以外的所有群

## 其他功能

- **严格模式**（默认开）：除了指令和消息监听，还会一起屏蔽被拦插件的事件钩子（LLM 请求前后、发送前装饰等）和 LLM 函数工具，原生规则做不到这一点
- **静默拦截**：被屏蔽插件的指令直接吞掉，不会掉进 LLM 闲聊里
- **指令冲突分流**：两个插件注册了同名指令时，可以让 A 群用插件 A、B 群用插件 B，互不干扰
- **命中测试**：输入会话 ID，列出这个会话里哪些插件能用、被拦的插件是被哪条规则拦的
- **一键导入原生规则**：把原生自定义规则里的插件禁用配置转成黑名单规则

## 聊天指令

仅管理员可用，本插件自己的指令不受任何规则限制，不会把自己锁在外面。

| 指令 | 说明 |
| --- | --- |
| `/pf status` | 查看当前会话命中的规则和可用插件 |
| `/pf bind <规则名>` | 把当前会话加入指定规则 |
| `/pf unbind` | 把当前会话从所有规则里移除（通配符规则不受影响） |

## 和原生规则的关系

- 原生「自定义规则」里的插件禁用配置**仍然有效**，两边会叠加生效。建议插件开关统一在本插件里配，原生那边只配人格、模型等其他项
- 用「导入原生」把旧配置转过来，保存确认没问题后，去原生自定义规则里**只删插件那一项**，别把整个会话的规则清掉
- 严格模式会和配置文件里的「启用插件」集合取交集，不会放出配置文件本来就没启用的插件

## 已知限制

- 被屏蔽插件里带权限限制的指令，非管理员触发时仍可能收到 AstrBot 的「权限不足」提示，因为 AstrBot 在会话过滤之前就做了权限判断。可以在平台设置里关闭「无权限回复」规避
- 指令冲突分流的前提是两个同名指令在 AstrBot 的「指令管理」里都处于启用状态，在那里被禁用的指令是全局禁用的，本插件无法恢复
- 本插件通过包装 AstrBot 内部的 `SessionPluginManager.filter_handlers_by_session` 实现过滤，卸载或停用插件时会自动还原

## 数据

规则保存在 `data/plugin_data/astrbot_plugin_session_plugin_filter/rules.json`，可以直接备份。

## 兼容性

AstrBot >= 4.26
