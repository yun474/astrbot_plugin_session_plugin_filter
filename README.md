# 会话插件过滤

按会话给 AstrBot 插件开**白名单 / 黑名单**，带可视化配置面板。

原生「自定义规则」只能一个会话一个会话地禁用插件（黑名单），想让某个群只能用几个插件得把其他插件挨个点掉，装了新插件还得回去补。这个插件就是来解决这个问题的。

## 功能

- **白名单模式**：只有勾选的插件能在这些会话里响应，其余全部屏蔽，新装的插件默认也被挡在外面
- **黑名单模式**：勾选的插件被屏蔽，其余照常
- **一条规则管多个会话**：同一套插件组合不用每个群配一遍
- **通配符会话**：`*:GroupMessage:*` 一把梭所有群，`aiocqhttp:FriendMessage:*` 管所有 QQ 私聊
- **严格模式**：除了指令和消息监听，还会一起屏蔽被拦插件的事件钩子（LLM 请求前后、发送前装饰等）和 LLM 函数工具，原生规则做不到这一点
- **静默拦截**：被屏蔽插件的指令直接吞掉，不会掉进 LLM 闲聊里
- **指令冲突分流**：两个插件注册了同名指令时，可以让 A 群用插件 A、B 群用插件 B，互不干扰
- **可视化面板**：搜索勾选插件、从已知会话里挑群、命中测试实时预览
- **一键导入原生规则**：把原生自定义规则里的插件禁用配置转成黑名单规则

## 使用

1. 安装插件后，在 WebUI 的插件详情页（或侧边栏的插件视图）打开「会话插件过滤」面板
2. 新建规则 → 选模式 → 勾插件 → 添加会话 → 保存，立即生效，不用重启
3. 会话 ID 可以在聊天里发 `/sid` 拿到，也可以直接在面板的会话搜索框里按群名找

### 聊天指令

仅管理员可用，本插件自己的指令不受任何规则限制，不会把自己锁在外面。

| 指令 | 说明 |
| --- | --- |
| `/pf status` | 查看当前会话命中的规则和可用插件 |
| `/pf bind <规则名>` | 把当前会话绑定到指定规则（会先从其他规则里移除） |
| `/pf unbind` | 把当前会话从所有规则里移除（通配符规则不受影响） |

## 匹配规则

- 精确会话 ID 优先于通配符
- 同为精确或同为通配符时，按规则列表顺序，靠前的先命中（面板里可以上移/下移）
- 没命中任何规则的会话，所有插件照常工作
- 系统内置插件永远不受影响
- 通配符只认 `*`（任意字符）和 `?`（单个字符），其余字符都按字面量匹配

## 和原生规则的关系

- 原生「自定义规则」里的插件禁用配置**仍然有效**，两边会叠加生效
- 用「导入原生」把旧配置转过来，保存确认没问题后，就可以去原生自定义规则里把插件配置删掉了
- 导入的规则默认关闭严格模式，行为和原生保持一致，需要的话自己打开
- 严格模式会和配置文件里的「启用插件」集合取交集，不会放出配置文件本来就没启用的插件

## 已知限制

- 被屏蔽插件里带权限限制的指令，非管理员触发时仍可能收到 AstrBot 的「权限不足」提示，因为 AstrBot 在会话过滤之前就做了权限判断。可以在平台设置里关闭「无权限回复」规避
- 指令冲突分流的前提是两个同名指令在 AstrBot 的「指令管理」里都处于启用状态，在那里被禁用的指令是全局禁用的，本插件无法恢复
- 本插件通过包装 AstrBot 内部的 `SessionPluginManager.filter_handlers_by_session` 实现过滤，卸载或停用插件时会自动还原

## 数据

规则保存在 `data/plugin_data/astrbot_plugin_session_plugin_filter/rules.json`，可以直接备份。

## 兼容性

AstrBot >= 4.26
